{{- /* 一个标签页该显示成什么样子。 ## 为什么需要这个 Hugo 的分类词是**大小写合并**的：`Netflix` 与 `netflix` 归成同一个词 `netflix`， 一个页面。合并本身是对的——标签页属于投影这一层，投影本来就是有损、可重建的， 而把这两个当成两个标签会让人以为自己标错了。 但**显示成哪一种写法，Hugo 取的是它先遇到的那个**，而那取决于页面遍历顺序。 实测：同一份 canonical 连着生成两次，`tags/key.html` 的标题一次是 `Key`、 一次是 `KEY`——数据一个字节没变，产出却变了。 这类不确定不只是难看：这个仓库每次重新生成都会多出一条无意义的 diff， 而一份存档的价值有一半在于「没变的东西看得出没变」。 实测这份档案 712 个标签里有 14 组只差大小写： `Netflix`(66)/`netflix`(4)、`IT`(10)/`it`(1)、`key`(2)/`Key`(1)/`KEY`(1) 等等。 ## 取哪一种：用户实际用过的写法里排序最靠前的那个 **不首字母大写、也不全小写**——那都是替用户做的规范化，而这份档案里没有一处 该由我们来决定他的标签怎么拼。只在他真的用过的几种写法里挑一个。 先试过「取用得最多的那种」（`Netflix` 66 次胜过 `netflix` 4 次），但那要在模板里 用 dict 计数，而 Hugo 的 map 键有自己的一套大小写规则——实测 `pixar`(6) 反而输给 `Pixar`(4)，`MOBA`(3) 输给 `Moba`(1)。判据算错了却看不出来，因为结果一样像模像样。 改成排序取第一个：没有计数，就没有算错的余地，而稳定性才是这里要的东西。 换成现成的 Hugo 主题时，这个文件跟着 layouts/ 一起删。 */ -}} {{- $key := .Data.Term -}} {{- $variants := slice -}} {{- range .Pages -}} {{- range .Params.tags -}} {{- if eq (lower .) $key -}}{{- $variants = $variants | append . -}}{{- end -}} {{- end -}} {{- end -}} {{- $name := $key -}} {{- with sort (uniq $variants) -}}{{- $name = index . 0 -}}{{- end -}} {{- return $name -}}
